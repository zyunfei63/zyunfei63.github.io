go语言方面

③ crypto/tls（安全传输层）

  • 封装了什么：TLS/SSL 加密握手的底层逻辑。
  • 为什么好用：我们在 Java 里为了搞个自定义证书，要经历 SSLContext -> TrustManagerFactory -> KeyStore -> SocketFactory 的折磨。而在 Go 里，证书信任直接简化为： 简单、暴力、直接。

2. 文件与数据处理的“老黄牛”

④ io 与 io/ioutil（现在多被 io 和 os 替代）

  • 封装了什么：数据流的读取与写入。
  • 为什么好用：你在代码里用的 ioutil.ReadAll(resp.Body)，不管你发请求后服务器返回的是 1KB 的 JSON 还是 1GB 的文件，它底层都会通过流式读取（Stream）帮你全部安全地读出来。它能自动处理各种缓冲区。

⑤ encoding/json（JSON 序列化）

  • 封装了什么：JSON 字符串和 Go 结构体（Struct）之间的互相转换。
  • 为什么好用：Java 里你需要引入 Jackson、Fastjson 或者 Gson。而在 Go 里，标准库直接自带。更牛的是，你甚至不需要像 Java 那样给类加上一堆 @JsonProperty 注解，只需利用 Go 结构体的标签（Tag）： 然后 json.Marshal() 和 json.Unmarshal() 就能完美搞定。

3. 并发与同步的“神器”

这就是你刚才疑惑的 sync 包所在的区域，Go 的并发原语极其丰富。

⑥ sync（同步工具箱）

这里面全都是解决并发问题的利器：

  • sync.WaitGroup：就是你刚才用的，主线程等子线程，类似 Java 的 CountDownLatch。
  • sync.Mutex / RWMutex：互斥锁。多个协程抢同一个资源时，用它锁住。RWMutex 是读写锁（读共享，写独占），性能极高。
  • sync.Map：并发安全的 Map（你代码里 transportCache 用的就是它）。
  • sync.Once：保证某个代码块在程序生命周期内只执行一次（非常常用，比如用来做单例初始化、加载全局配置）。

⑦ time（时间大师）

  • 为什么好用：它不仅能格式化时间，还能玩转定时器和超时。比如你代码里的 time.Sleep。在网络编程中，经常用 time.After(3 * time.Second) 配合 select 来实现超时控制（Timeout）。

⑧ context（上下文/并发终结者）

  • 封装了什么：控制协程的生命周期。
  • 为什么好用：这是 Go 语言独有的设计。假设你有 100 个并发请求去请求第三方，其中一个超时了，或者用户取消了操作，你如何立刻通知另外 99 个协程“别干了，撤退”？用 context.WithCancel() 或者 context.WithTimeout() 就能实现级联取消。它彻底解决了协程泄露的问题。

总结：Go 的封装哲学

  • Java 的封装：是为了屏蔽复杂。比如 Spring 把复杂的 Bean 生命周期全封装起来，你只要加个 @Autowired 就行。
  • Go 的封装：是为了提供原语。Go 把网络、并发底层的核心机制直接暴露给你，不搞过度设计。你想换代理？直接改 Transport；你想加锁？直接用 sync.Mutex。

你在 Java 里研究透了连接池、TLS、线程池的原理，现在切到 Go，你会发现它的这些标准库工具包，其实就是你之前手写 Java 架构时的那些底层原语。知道底层原理，再用这些工具，你就能不仅“用得好”，还能“改得动”。
